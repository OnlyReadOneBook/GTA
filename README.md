# GTA Online 매크로

GTA V Enhanced(Steam, `GTA5_Enhanced.exe`) 온라인용 키 입력 매크로. AutoHotkey v2 로 `Main.ahk` 하나를 띄우면 아래 기능이 전부 올라온다. 메모리 읽기·인젝션·게임 파일 수정은 없고, 키보드·마우스 입력과 화면 캡처만 쓴다.

## 실행

```powershell
& "$env:LOCALAPPDATA\Programs\AutoHotkey\v2\AutoHotkey64.exe" "C:\Users\rlfjr\GTA\Main.ahk"
```

같은 폴더의 `Config.ini` 를 읽는다(없으면 알림창 뒤 종료). 다시 실행하면 이전 인스턴스를 교체한다. 시작하면 AFK 방지(`[Features] AntiAFK=1` 이고 `AFKOnStart=1` 일 때)와 오버레이(`OverlayEnabled=1`)가 켜진 채로 뜬다.

고친 뒤 검사는 같은 폴더의 사본으로 한다(`#Include Core\…` 가 상대 경로라 다른 폴더에서는 못 읽는다). `/validate` 는 실행하지 않고 문법만 본다.

```powershell
Copy-Item Main.ahk Main_check.ahk
& "$env:LOCALAPPDATA\Programs\AutoHotkey\v2\AutoHotkey64.exe" /validate /ErrorStdOut Main_check.ahk
[IO.File]::Delete("Main_check.ahk")
```

## CI와 배포 패키지

GitHub Actions의 [CI](.github/workflows/ci.yml)는 Windows에서 AHK 문법, PowerShell·Python 구문, 게임 입력 없는 회귀검사를 실행한다. 실제 게임 입력·화면 캡처·GPU 측정·작업 스케줄러 실행은 포함하지 않는다. 검사 도구와 고정한 실행기 버전은 [tools/ci](tools/ci/README.md), 구성요소와 현장 시험의 경계는 [도구 경계](docs/tool-boundaries.md)에 있다.

로컬에서도 Windows PowerShell 5.1에서 같은 검사를 실행한다. Python 3가 PATH에 있어야 하며, 다른 실행기를 쓰면 `run-checks.ps1 -PythonPath`로 지정한다. AutoHotkey는 임시 디렉터리에 압축만 풀어 기존 설치를 유지한다.

```powershell
$ciDirectory = Join-Path $env:TEMP ('gta-ci-' + [guid]::NewGuid().ToString('N'))
$ahk = & .\tools\ci\install-autohotkey.ps1 -Destination (Join-Path $ciDirectory 'ahk')
& .\tools\ci\run-checks.ps1 -AhkPath $ahk -OutputDirectory (Join-Path $ciDirectory 'checks')
& .\tools\ci\package-macro.ps1 -CheckResults (Join-Path $ciDirectory 'checks\results.json') -OutputDirectory (Join-Path $ciDirectory 'package')
```

패키지는 검사를 통과한 소스와 이미지, 캡처 런타임, 기능을 꺼 둔 `Config.example.ini`, 파일별 SHA-256을 담는다. 실제 `Config.ini`는 포함하지 않는다. 처음 설치할 때 예제를 `Config.ini`로 복사해 검토하고 필요한 기능을 켠다. 기존 설치를 갱신할 때는 설정을 보존한다. 패키지 생성은 매크로 재시작·실행 파일 설치·작업 스케줄러 갱신을 수행하지 않는다.

## 입력 중단 원인 확인

수익 자동화는 실제 사용자 입력과 GTA 포커스 판정 실패를 구분해 중단 사유를 표시한다. 두 조건이 함께 감지되면 둘 다 기록한다. 중단 순간의 물리 입력 유휴 시간, 입력 감시 시작 후 경과 시간, GTA 창 판정 결과와 전면 창 HWND·PID·실행 파일·제목은 `%TEMP%\gta-earn.log`에 남는다. 최초 감지 사유는 후속 화면 판독 실패와 별도로 보존하며 같은 회차의 재시도 안내에도 사용한다. 창 제목에는 다른 앱의 문서명 등이 포함될 수 있으므로 로그를 외부에 공유하기 전에 확인한다.

포커스 판정 실패 기록만으로 특정 앱이 포커스를 가져갔다고 단정하지 않는다. 당시 전면 창 정보와 녹화·입력 기록을 대조한다. 실제 포커스 이탈이나 사용자 입력이 감지되면 즉시 입력을 멈추고 키를 놓는 보호 동작, 불확실한 거래의 재요청 금지는 그대로 유지한다.

## 사용법을 보는 곳

- 게임 안: `Num.` 한 번이면 현재 키맵 툴팁이 8초 뜬다(다시 누르면 닫힘). 2초 안에 두 번 누르면 설정 창이 열린다.
- 설정 창: 트레이 아이콘 더블클릭, 또는 트레이 메뉴 "설정 창 열기". 노트북 화면(GTA 가 없는 모니터) 가운데에 뜬다. 지금 상태, 기능 실행 버튼, `Config.ini` 값 저장, 최근 로그(`gta-macro.log`·`gta-afk.log` 끝 15줄씩)가 한 창에 있다. 실행 버튼은 GTA 를 앞으로 가져온 뒤 누르고, 두 번 눌러야 하는 기능은 키(2초)와 달리 3초 안에 두 번 누른다.
- 트레이 메뉴: 설정 창 열기 / 단축키 보기 / 외출 저부하 켜기·끄기 / AFK 방지 켜기·끄기 / 전체 멈춤 / 종료.
- 오버레이: 기본은 게임 오른쪽 위(돈 표시 아래)이며, 도는 기능과 AFK 상태가 한 줄씩 보인다. 클릭이 통과하고 게임에 입력을 보내지 않는다. 위치(`OverlayXPct`·`OverlayYPct`)가 화면 감지 영역(오른쪽 아래 구석, 왼쪽 위, 화면 가운데)을 덮으면 설정 위치에 가장 가까운 안전한 경계로 이동한다. 오른쪽 아래에 둔 상태에서 알림 줄이 늘어나도 위쪽 기본 위치로 돌아가지 않고, 감지 영역을 피하는 데 필요한 만큼만 옮긴다. 창이 너무 커서 안전한 자리가 없으면 숨으며 설정값은 바꾸지 않는다.
- 이 파일과 `Config.ini` 의 주석.
- 조사·실측 기록(작텔이 되는 조건, 봇 절차, 막힌 방법, 되돌리는 절차): dotfiles 의 `claude/skills/gta-online-research/SKILL.md`. 아래에 "0926 실측" 이라 적은 것은 거기에 근거가 있다.

## 외출 저부하 모드

자동 전환은 `Config.ini [Settings] AutoAwayIdleSec=60`처럼 유휴 초를 설정해 켠다. 기본값 `0`은 자동 전환을 끈다. 수동 외출이 꺼져 있으면 사람이 설정 시간 동안 조작하지 않을 때 CPU 부스트 끔·30 FPS·G-Helper Silent로 전환하고, 다시 조작하면 Turbo와 CPU·FPS 일반 정책으로 돌아간다. 수익 자동화가 꺼져 있어도 적용한다. 매크로 자신의 AFK·메뉴 입력은 유휴 시간을 초기화하지 않으며, 물리 입력·기존 감시가 식별한 외부 주입 입력·계속 누르고 있는 이동 키는 활동으로 취급한다. 외부 원격 입력이 매크로의 자기 입력 구간과 겹치면 기존 유휴 감시가 둘을 구분하지 못할 수 있다. 수동 `AwayMode=1`은 자동 전환보다 우선한다.

자동 전환에는 트레이 클릭, 전역 단축키, 게임 포커스 이동이 필요 없다. 매크로가 2초 간격으로 상태를 발행하고 감시 프로그램이 약 1초 간격으로 소비한다. 감시 프로그램은 같은 신호로 모드와 FPS 요청을 갱신하므로 긴 매크로 작업의 종료를 기다리지 않는다. 측정이나 RTSS helper의 확인 주기 때문에 수 초의 추가 지연은 있을 수 있다. `.gta-away-want`의 발신 프로세스와 15초 이내 상태만 신뢰하며, 신호가 끊기면 자동 저부하는 해제한다. 수동 외출 설정은 신호와 별개로 유지한다. 새 기능의 최초 설치에는 매크로·감시 프로그램 갱신이 필요하지만 GTA 재시작은 필요 없다.

트레이 아이콘을 우클릭하고 외출할 때 "외출 저부하 켜기 (30 FPS)", 돌아오면 "외출 저부하 끄기 (일반 복귀)"를 선택한다. GTA와 매크로를 재시작하거나 세션을 옮길 필요가 없다. 켜짐 상태는 `Config.ini [Settings] AwayMode=1`로 저장되며, 매크로를 나중에 다시 실행해도 유지된다. 매크로의 CPU 전력 적용은 낮은 우선순위 타이머가 처리한다. 별도 감시 프로그램은 입력 구간과 관계없이 외출 FPS 요청을 동기화한다.

- 켜짐: CPU 부스트를 끄고 기존 RTSS helper에 30 FPS 제한을 요청한다. G-Helper 성능 모드도 Silent로 전환한다. 수익 자동화가 잠시 멈추거나 사람이 입력하거나 매크로가 메뉴를 조작해도 수동으로 끄기 전까지 유지한다. `CpuBoostIdleSec=0` 또는 `IdleFpsLimit=0`이어도 외출 모드의 고정 정책이 우선한다.
- 꺼짐: 기존 CPU·FPS 일반 자동 정책으로 돌아간다. 일반 정책은 사용자 활동 중 CPU 부스트를 켜고 RTSS 제한을 해제하며, 수익 자동화 중 설정된 유휴 시간이 지나면 다시 절전한다. RTSS 제한 해제는 게임 자체의 VSync·프레임 제한까지 바꾸는 동작이 아니다.
- 그래픽 설정 파일, 해상도, 텍스처, 프레임 생성은 변경하지 않는다. 평소 화질과 화면 인식 조건을 보존하는 무재시작 저부하 모드이며, 모든 그래픽 항목을 최저로 바꾸는 프리셋은 아니다.
- FPS 적용에는 설치되어 실행 중인 "GTA FPS Helper"와 RTSS가 필요하다. 트레이 체크와 툴팁은 선택한 모드이며, 적용 대기와 실제 반영은 다르다. `gta-earn.log`의 CPU 부스트·FPS 요청 성공 기록은 전력 명령 완료와 요청 파일 저장을 뜻한다. 실제 FPS 반영은 `%USERPROFILE%\.gta-fps-helper.log`의 `fps=30`과 프레임 측정으로 확인한다. 설정·전력·요청 저장 실패는 성공으로 기록하지 않고 로그에 남긴다.
- 외출 모드는 수익 자동화나 AFK 보호를 켜거나 끄지 않는다. F9 수익 자동화와 AFK 상태는 별도로 유지하며, 재고가 가득 찼다는 이유로 자동화를 중단하지 않는 기존 정책도 그대로다.
- Discord HUD는 `[Settings] DiscordHUDAppID`에 Store AppUserModelID가 있으면 패키지 앱을 활성화하고, 값이 비면 기존 `DiscordHUDPath` 실행 파일 경로를 사용한다. 기존 데스크톱 프로세스는 강제 종료하지 않는다. Store 앱 활성화·렌더링·실제 창 식별은 설치된 앱을 실행한 뒤 별도로 확인해야 한다.
- DiscordChatHUD 본체는 입력 감시가 붙은 매크로가 MCT를 조작하는 동안만 숨긴다. 직접 조작하는 MCT·벙커·나이트클럽·창고 PC, 외출 모드, 수익 자동화 켜짐, 대기, 전화·Vinewood 앱·금고·직원 파견은 숨김 사유가 아니다. MCT 열기 또는 매크로의 MCT 제목 확인으로 시작한 보호만 하위 사업장·결제 화면까지 유지하며, 유휴 화면 검색으로 숨김을 시작하지 않는다. MCT 닫힘, 사용자 입력·포커스 이탈 감지, 중단 또는 작업 감시 종료 때 원래 보였던 본체를 포커스 없이 복원한다. 복원 실패는 기록하고 재시도하며 게임 입력 중단과 키 해제는 계속한다. 원래 숨긴 창, 최소화한 창, 설정·로그인 창은 변경하지 않는다.
- 수동 MCT 조작과 작업 중단 뒤에는 입력·OCR 없는 저우선순위 확인으로 표시 상태를 맞춘다. MCT 제목과 사업장 화면을 제한된 영역에서 나누어 확인하며, 화면을 못 읽은 것만으로 닫혔다고 간주하지 않는다. GTA가 앞이 아닐 때는 복원하고, 열린 MCT로 돌아오거나 HUD가 자체적으로 다시 표시되면 다음 안전한 확인 구간에서 다시 숨긴다.
- HUD 숨김 확인에 실패하면 해당 화면 판독·거래를 시작하지 않는다. MCT 닫힘 뒤 HUD 복원이 실패해도 확인된 게임 화면의 일어서기·CEO 해제는 계속한다. HUD 오류와 창 복원 책임을 유지하고 1초 타이머에서 재시도하며, 실제 표시를 확인해야 복원 완료를 기록한다. 게임 정리 완료와 HUD 복원 대기는 별도 상태다. Main 정상 종료·재시작에도 소유한 HUD를 복원하지만, 강제 프로세스 종료로 종료 콜백이 실행되지 않는 경우에는 자동 복원을 보장하지 않는다. 이때는 DiscordChatHUD에서 직접 표시 상태를 선택한다.

### G-Helper 조용한 모드 연결

기존 시작 프로그램 `GTA Turbo.lnk`가 실행하던 `scripts\gta-turbo.ps1`의 정본은 이제 `Core/gta-turbo.ps1`이다. 해당 시작 항목의 실행 파일을 이 소스로 갱신해 사용한다. 기본 설정 경로는 `%USERPROFILE%\GTA\Config.ini`이며, 다른 위치에서는 `-MacroConfig`를 명시한다. G-Helper가 실행 중이어야 한다. 다른 모드 강제 프로그램과 동시에 실행하지 않는다.

단계별 진단에는 `Core/gta-stage-trace.ps1`도 감시기와 같은 폴더에 배포한다. FPS helper 설치 스크립트는 두 파일을 RTSS 폴더에 함께 설치한다. `%USERPROFILE%\gta-perf\stage-trace\watcher.jsonl`과 `fps-helper.jsonl`에는 호출 전 `begin`, 정상 반환 `end`, 예외 `error`와 단조 시계 기반 `duration_ms`가 남는다. 각 행의 실행 ID, PID·시작 시각, 실행 파일 경로·SHA256으로 현재 실행을 구분한다. 파일당 8 MiB와 백업 3개로 제한하며 기록 실패는 제어에 전파하지 않는다. 모듈이 누락되면 제어는 계속되지만 단계 기록은 남지 않으므로 배포 뒤 현재 실행 ID의 새 행을 확인해야 한다.

`policy.observed`는 감시기가 매크로의 복귀 신호를 읽은 시각과 송신 PID·tick이다. 실제 키 입력 시각과 같다고 해석하지 않는다. `fps.request.observed` 이후 RTSS의 load/set/save/update 각각을 확인하고, 반환값 `ok=false`를 정상 적용으로 해석하지 않는다. `begin`만 있고 종료 행이 없는 호출은 조사 후보이며 강제 종료·회전으로 기록이 빠진 경우와 구분한다. 이 기록은 다음 지연을 분해하기 위한 것으로 과거 지연의 원인을 소급 확정하지 않는다.

- 감시 프로그램은 UI Automation으로 기존 G-Helper의 Silent·Balanced·Turbo 버튼을 식별한 뒤, 관측한 직접 부모에 표준 `WM_COMMAND/BN_CLICKED` 알림을 제한 시간과 함께 보낸다. UIA Invoke는 실기기에서 포커스 이동이 확인되어 사용하지 않는다. 숨겨진 창은 모니터 바깥에서 `ShowWindow(SW_SHOWNOACTIVATE)`로 지연 생성된 버튼까지 준비한 뒤 원래 위치와 숨김 상태로 되돌린다. 키·마우스 입력, 게임 전면화, GTA 재시작, GPU/MUX 변경은 사용하지 않는다. 버튼과 모든 부모의 활성 상태를 다시 확인하며, 확인창 때문에 비활성화됐거나 사용자가 G-Helper를 직접 조작하거나 보안 데스크톱이 열려 있으면 기다린다.
- G-Helper 기본 모드 Silent·Turbo를 선택한다. 확인되지 않은 버튼은 추측하지 않고 오류를 기록한다. 설정 값과 새로운 ACPI 적용 로그의 `Mode = N : OK`를 함께 확인한다. 설정 값만 바뀐 상태는 완료가 아니다. 미확인 전환 요청은 5분에 한 번으로 제한한다.
- GTA5_Enhanced가 실행 중이고 외출 상태가 아니면 Turbo, 자동·수동 외출 상태이거나 GTA가 없으면 Silent로 맞춘다. 사용자 입력으로 자동 외출이 해제되면 이전 모드와 관계없이 Turbo로 복귀한다. 감시 프로그램 시작·재시작 시에도 같은 정책을 적용하며, 유효한 자동 신호가 끊기면 자동 외출을 해제한다. 수동 외출 우선권과 CPU 부스트·30 FPS 정책은 유지한다.
- G-Helper의 지연 전력 적용을 기다린 뒤 최신 요청을 다시 읽어 CPU 상한과 부스트를 맞춘다. 일반 복귀에서도 CPU 최대 100%와 부스트를 복원한다. 외출 중에는 감시 프로그램도 30 FPS 요청을 갱신하고, 유효한 사용자 복귀 신호에는 제한 해제(0)를 요청한다. 요청 파일은 최신 정책을 다시 확인한 뒤 원자적으로 교체하며, 실제 RTSS 적용은 기존 FPS helper가 담당한다. 자동 외출이 꺼졌거나 외출과 관계없는 일반 유휴 FPS 값은 매크로가 관리한다. 그래픽 설정은 변경하지 않는다. `%LOCALAPPDATA%\gta-turbo.log`의 적용 또는 대기 기록과 `%APPDATA%\GHelper\log.txt`를 대조한다. 기존 `%LOCALAPPDATA%\gta-perf\YYYYMMDD.csv` 측정은 유지하며, 모드 제어 오류로 측정을 중단하지 않는다.

입력 없는 회귀 검사는 `powershell.exe -NoProfile -File tools/tests/gta-mode.tests.ps1`이다. 실제 G-Helper와 키 입력을 대역으로 격리하며, CI에서는 전체 Windows 검사에 포함한다.

G-Helper와 같은 .NET 10의 지연 버튼 생성 검사는 PowerShell 7.6 이상에서 `pwsh -NoProfile -File tools/tests/gta-mode-window.integration.ps1`로 별도 실행한다. 독립된 테스트 창만 화면 밖에 표시하고 버튼 생성, 숨김 복원과 전면 창 보존을 확인한다. G-Helper나 GTA는 조작하지 않는다.

## 키

게임 창이 앞일 때만 잡힌다(종료만 전역. 스팀 봇 작텔이 도는 동안은 전체 멈춤도 모든 창에서 잡힌다). 밖에서는 F키·넘패드가 원래대로 동작한다. ×2 는 2초 안에 두 번 눌러야 실행되는 기능이다(첫 누름에 "한 번 더 누르면 실행" 툴팁. 꾹 누르고 있는 자동 반복은 두 번째로 세지 않는다). 키 배정은 `Config.ini [Hotkeys]`, 쉼표로 여러 키를 붙일 수 있고 같은 키를 두 기능에 주면 먼저 등록된 쪽만 잡힌다.

## 작텔 (잡 워프)

둘 다 일시정지 지도에서 작업 블립을 골라 화면 아래에 "Start Job (Space)" 가 보이는 상태에서 누른다. 실내면 `P` 다음 `CapsLock` 으로 전체 지도. 도착지는 그 작업의 출발점이다. 두 작텔은 동시에 돌지 않는다(한쪽의 Enter 가 다른 쪽 확인창에 들어가는 것을 막는다).

즐겨찾기한 남의 작업은 지도에 블립이 안 뜬다(내가 만든 작업만 뜬다, 0926 실측). 그런 작업은 `P` → ONLINE → Jobs → Play Job → Bookmarked 에서 골라 CONFIRM 창이 뜬 상태에서 F10 두 번(매크로가 CONFIRM 을 보면 Space 를 건너뛰고 Enter 부터 한다). F11 은 화면을 보지 않고 Space 부터 보내므로 지도에서만 쓴다.

임무 진행 중에는 Jobs가 `Jobs are currently unavailable.`로 막혀 위 목록 경로를 쓸 수 없다. 0927 페이폰 히트에서 기존 웹 기록과 같은 결과를 확인했다(확인 화면은 로컬 `docs/evidence/2026-09-27-payphone-jobs-unavailable.png`).

### 준비 작업 전 Quick Join 적용 순서

아래는 2026-09-27 대조한 웹 원문의 절차다. 로컬에서 Quick Join 없이 시작한 페이폰 히트는 Jobs 접근 불가까지 확인됐으며, 그 시험은 완료됐다.

1. Online → Options에서 `Matchmaking=Closed`, `Filter Quick Join Content=User Created Only`로 설정하고 필요한 지도 작업 표식을 표시한다.
2. 보스 미등록 상태에서 전화 `Quick Join → Random → Alone → Yes`로 검색한다. `Looking For Job`을 확인한 뒤 CEO/MC 등록으로 검색을 끝내고 prep를 시작한다.
3. 이미 보스라면 검색 → prep 시작 → 전화 Quick Join에 다시 접근 → 폰 닫기로 검색을 취소하는 순서를 쓴다. 두 경로 중 현재 상태에 맞는 하나를 적용한다.
4. 지도 작업 블립에서 시작한 뒤 아래 F11 절차를 쓴다. 이 준비는 prep마다 필요하며, 필터는 검색을 늦출 뿐 매칭을 막지는 않는다.

출처는 [2024-12-30 작성자 절차](https://www.reddit.com/r/gtaglitches/comments/1hpoqk9/job_warping_during_missions_update/)와 기존 조사에서 인용한 [한국어 가이드의 작업 텔레포트 절](https://www.namu.moe/w/Grand%20Theft%20Auto%20Online/가이드)다. 원문의 2025-03-08 댓글은 PC 카지노 prep에서 Alt+F4 후 60초 대기로 성공했다고 보고한다(Legacy/Enhanced 구분·세부 버전 미기재). 일부 임무의 취소·운반물 유실도 원문에 명시돼 있어 모든 prep의 유지 보장은 아니다. 이 계정의 유지 성공 실측은 아래 페이폰 히트 두 건이며, 웹 보고와 구분한다. 조사 원자료와 과거 invalid 작업 경로는 dotfiles의 `claude/skills/gta-online-research/SKILL.md`에 정리했다.

### F11 두 번: Alt+F4 방식

#### 퀵 조인 준비까지 F11 로 (`JobWarpQuickJoin=1`)

F11 두 번을 두 단계로 쓴다. prep 을 시작하기 전(보스 해제가 되는 때)에 누른다.

1. F11 두 번: 매크로가 보스 해제 → 폰 Quick Join → Random → Alone → Yes → 곧바로 보스 등록(`JobWarpBossRole`, 기본 CEO)까지 하고 오버레이에 "작텔 준비됨" 을 띄운다. Looking For Job 은 기다리지 않는다. Yes 까지 눌렸으면 검색은 시작됐고, 바로 등록해야 검색이 작업 로비를 잡기 전에 끝난다.
2. 직접: prep 을 시작하고, 지도에서 작업 아이콘에 커서를 올려 "Start Job (Space)" 가 보이게 한다.
3. F11 두 번: 아래 Alt+F4 작텔. 성공하면 준비 상태가 풀린다. 준비 상태는 `JobWarpArmMaxMin`(30분)이 지나도 풀린다.

옛 재등록 텔레포트와 순서는 같지만 칸 수를 세지 않는다. 폰 앱·목록 줄·상호작용 메뉴 줄을 누르기 전마다 `Images\JobWarp\1920x1080\` 템플릿으로 선택된 줄을 확인하고, 안 보이면 더 누르지 않고 멈춘다(까닭은 툴팁과 `gta-macro.log` 의 `[jobwarp]` 줄). 템플릿 목록은 `Features/Teleport/QuickJoinPrep.ahk` 맨 위. 1920x1080 CEO 템플릿은 0927 에 떠서 `JobWarpQuickJoin=1` 로 켜 두었다. 0927 저택 안 실제 시험에서 F11 두 번 뒤 약 18초에 "작텔 준비됨" 이 됐고(Yes 뒤 폰은 저절로 닫히고, 약 3.5초 뒤 CEO 등록), 그 뒤 95초 동안 작업 로비로 끌려가지 않았다. 0928 에 실외(Vinewood 길가)에서도 뜨도록 템플릿을 실내·실외 원본을 겹쳐 다시 떴고(까닭은 `tools/build-jobwarp-templates.ps1` 머리말), 같은 자리 흐린 낮 실제 시험에서 F11 두 번 뒤 약 18초에 "작텔 준비됨" 이 됐다. MC(`JobWarpBossRole=MC` 나 MC 상태)와 다른 해상도는 템플릿이 없어 그 단계에서 멈추니, 그때는 템플릿을 더 뜨거나 `JobWarpQuickJoin=0` 으로 두면 F11 이 예전처럼 바로 작텔한다.

1920x1080 템플릿은 `tools/build-jobwarp-templates.ps1` 이 `docs/evidence/2026-09-27-jobwarp/` 의 실측 화면(코드가 찾는 영역 그대로 자른 무손실 PNG, 전체 화면은 같은 이름 JPG)에서 잘라 만들고, 같은 스크립트가 모든 원본에 코드와 같은 영역·옵션으로 대 보아 맞는 상태에서만 찾히는지 표로 확인한다(`-TestOnly` 는 시험만). 새로 뜰 때는 `tools/jobwarp-capture.ps1` 로 찍는다. 백그라운드로 띄워 두면 App menu 키(오른쪽 클릭 메뉴 키)를 한 번 눌러 켠 동안, 또는 ScrollLock 이 켜진 동안만 게임 모니터를 찍고 앞 장과 달라진 화면만 `%TEMP%\claude\jobwarp\` 에 남긴다(게임에 키를 보내지 않는다). 켜고 손으로 한 번 보스 해제 → Quick Join → Random → Alone → Yes → 보스 등록을 한 뒤 App menu 키를 다시 눌러 끄면, 남은 장에서 선택된 줄을 잘라 템플릿을 만든다.

```powershell
Start-Process powershell -ArgumentList '-NoProfile -ExecutionPolicy Bypass -File tools\jobwarp-capture.ps1' -WindowStyle Hidden
```

사전 설정: Online → Options → Matchmaking = Closed, 상호작용 메뉴 → Preferences → Map Blip Options → Jobs 표시.

Space → CONFIRM Enter → 바로 Alt+F4 → 게임 종료 확인창에서 60초가 지나고 오른쪽 아래 No/Yes 안내가 보이면 Backspace(No). 작업 로딩이 뒤에서 튕기고 나면 작업 위치 프리모드에 떨어진다. 0926 페이폰 히트에서 목표·타이머를 유지한 채 두 번 성공했으나, 그때는 Quick Join으로 다른 작업 로비를 다녀온 뒤 지도에 작업 블립이 보이는 상태였다. 0927 Quick Join을 쓰지 않은 페이폰 히트에서는 지도 작업 블립이 사라졌다. 임무 중 항상 지도 작텔을 시작할 수 있다는 뜻은 아니다.

- No/Yes 안내는 20초쯤에 뜨지만 그때 누르면 작업 로비로 들어간다(0926 실측: 32초 실패, 60초 성공 2회). `JobWarpMinWaitMs=60000` 을 줄이지 않는다.
- 90초까지 안내를 못 찾거나 대기 중 End 를 누르면 매크로는 Backspace 를 안 보낸다. 종료 확인창은 직접 Backspace 로 닫는다. Enter(Yes)는 게임이 꺼진다.
- 로비로 들어갔으면 Backspace → Yes 로 나오면 원래 자리.
- 오버레이가 "작텔 대기 N/60초" 를 보여 준다. 안내 감지 자리가 오른쪽 아래 구석이라 오버레이를 거기에 두지 않는다.

### ScrollLock 두 번: Rockstar 친구 텔

지도에서 작업 블립을 고르거나 작업 시작 CONFIRM 창에서 실행한다. Home 친구 목록에서 `-Atra_Mora-` 이름과 같은 카드의 `JOIN GAME`을 확인한 뒤 목록을 닫고 작업을 시작한다. 로딩 중 Home을 다시 열어 이름을 새로 찾아 참가한다. 참가·조준 모드·호환성 알림은 확인한 종류에만 Enter를 보낸다.

- 친구 목록의 순서는 고정하지 않는다. 현재 화면에 없으면 위로 스크롤한 뒤 아래로 탐색한다. 버튼은 찾은 이름과 같은 카드 안에서 검색하고, 클릭 직전 이름과 버튼 위치를 다시 대조한다.
- 대상이 오프라인이거나 `JOIN GAME`이 없으면 멈춘다. 다른 친구나 `INVITE TO GAME`을 대신 선택하지 않는다.
- 제공된 화면에서 추출한 `Images/FriendWarp/1920x1080` 템플릿을 사용하므로 현재 지원 해상도는 1920×1080이다.
- End, 물리 입력, 포커스 이탈, 알 수 없는 알림, 종료 확인창에서는 중단한다. 중단 시 남은 Home 화면·작업 로딩은 직접 확인한다.
- F10 스팀 봇과 F11 Alt+F4는 그대로 유지한다. 친구 텔은 다른 작텔·입력 매크로와 동시에 실행하지 않는다.
- 알림 처리와 HUD 복귀만으로 도착 위치·세션 유지·준비 임무 유지까지 확인하지 않는다.

### F10 두 번: 스팀 봇 방식

작업 시작 → 로딩 중 스팀 그룹 채팅 "CCYXJ差传" 의 봇(`BotWarpBotRow` 1: 差传CCYXJ01, 2: 差传CCYXJ03)에 Join Game → "join a different session" Enter → (조준 모드가 다르면 경고 Enter) → "incompatible assets" Enter → 약 20초 뒤 출발점. 60초 대기가 없어 F11 보다 빠르다.

이 방식의 로컬 성공은 새 세션의 프리모드 도착이다. 진행 중인 prep가 유지됐다는 실측은 없으며, [2026년 PC Enhanced 봇 가이드](https://www.reddit.com/r/gtaglitches/comments/1qaewlg/pc_enhanced_gtav_job_teleport_guide_3_easy/)도 prep 유지 여부는 설명하지 않는다. 따라서 Steam 봇의 prep 유지·소실은 미확정이며, Alt+F4의 임무 유지 결과를 봇 방식에 적용하지 않는다.

- 준비: 스팀 그룹 채팅 창을 열어 둔다(매크로가 노트북 화면 오른쪽 위로 옮긴다. 필터 칸은 좌표로, 봇 줄과 Join Game 은 `Images\BotWarp\steam\` 참조 이미지로 찾은 자리를 누른다). 노트북 화면 배율 175%, 게임 16:9. `join_game.png` 가 없으면 시작하지 않는다. 봇이 게임 중(멤버 목록에서 초록 글자)이어야 한다.
- 채팅 창이 없으면 `open_in_steam.png`·`join_group_chat.png` 가 있을 때만 초대 링크로 자동으로 연다(친구 목록 창이 없으면 매크로가 먼저 띄운다. 0926 실측: 친구 목록이 한 번도 안 뜬 상태에서는 Open in Steam 이 무반응). 두 장이 없으면 채팅 창을 직접 열어 두라고 알리고 멈춘다.
- 메뉴 매크로·인형 뽑기·수익 자동화·이동·자동 클릭 토글이 켜져 있으면 시작하지 않는다.
- 도착한 세션은 새 세션이다(초대 전용이 아니다). 거기서 다시 Start Job 을 누르면 "Currently unavailable" 이 뜨니 매크로가 Backspace 로 닫고 멈춘다. F5 두 번으로 초대 전용에 옮긴 뒤 다시 한다. 세션을 옮긴 직후에는 지도에 블립이 한동안 없다. 그때는 위의 Play Job 경로.
- 조준 모드 경고를 거절(Backspace)하는 옛 방식은 게임이 13분 넘게 멈춘다(0926 실측). 수락하면 조준 모드가 봇 쪽으로 바뀐다(0926 실측: Assisted Aim - Partial). 초대 전용 세션 위주면 되돌릴 필요가 거의 없고, 되돌리는 절차는 조사 스킬에 있다.
- Join Game 뒤에 키보드를 만지면 사용자가 넘겨받은 것으로 보고 멈춘다. Join Game 뒤 20초 안에 참가 알림이 안 뜨면 멈추는데 작업은 로딩 중이니 봇에 직접 Join Game 하거나 작업을 나간다. incompatible 알림 없이 게임 화면으로 돌아오면 봇 세션에 들어갔을 수 있으니 위치를 확인한다.
- 중단은 End(스팀 창이 앞이어도 먹는다). 스팀 클릭·검색어 입력 전 대기 중에 End를 누르거나 스팀이 포커스를 잃으면 남은 입력 없이 멈춘다. Join Game 클릭 직후 대기에서 중단해도 GTA를 앞으로 가져오는 다음 단계로 넘어가지 않는다. CONFIRM 대기 중에 멈췄으면 확인창을 직접 Backspace 로 닫는다.
- KeyHoldTest.ahk·LCtrlSpammer.ahk 도 F10 을 쓰니 같이 켜지 않는다.

## 초대 전용 세션 (F5 두 번)

`P` → ONLINE → Find New Session → Invite Only Session → 확인창 OK. 줄 수를 세지 않고, ONLINE 목록에 들어간 뒤부터는 오른쪽 칸 제목과 확인창 문구를 템플릿(`Images\Session\1920x1080\`)으로 확인한 뒤에만 Enter 를 보낸다. 게임을 켠 방식에 따라 ONLINE 목록 길이가 달라 줄 높이로 세면 Quit to Story Mode 에서 Enter 가 나갔다(0926). 제목을 못 찾거나 마지막 확인창 문구가 3초 안에 "quit this session" 으로 확인되지 않으면 추가 입력 없이 멈춘다. 템플릿이 1920x1080 것뿐이라 다른 해상도는 안 된다.

## AFK 방지 (F4)

실제 키보드·마우스 입력이 45초 없을 때만 200초(±20초)마다 마우스를 오른쪽 2만큼 움직이고 100ms 뒤 왼쪽 2만큼 되돌린다. 일반·MCT 모드에 같은 방식을 사용하며 키·클릭·메뉴 전환은 보내지 않는다. 사용자 입력, 눌린 키, 포커스 이탈 또는 다른 매크로의 입력 소유가 확인되면 중단한다. 기존 입력 잠금과 전면화 조건을 유지한다. 로그의 `mouse pulse`는 입력 실행 기록이며 장시간 접속 유지 효과는 게임에서 별도로 검증한다. End는 AFK 방지를 끄지 않는다.

다른 창이 GTA 포커스를 가져가 있으면 입력이 없는 시간을 두 가지로 재서 가른다. 하나는 물리 입력(`A_TimeIdlePhysical`, 키보드·마우스 훅)이고, 다른 하나는 크롬 원격 데스크톱·computer-use·코덱스처럼 다른 프로그램이 주입한 입력까지 세는 전체 입력(`A_TimeIdle`, 이 매크로 자신의 입력은 뺀다)이다.

| 입력 없음 | 동작 |
|---|---|
| 둘 중 하나라도 `AFKRefocusIdleSec`(기본 300초) 미만 | 누가 자리에 있거나 다른 창을 쓰는 중이라고 보고 창을 뺏지 않는다. `skip: GTA 포커스 없음, 전면화하지 않음 (idle=Ns, 주입 포함 idle=Ms, 기준 300s)` 을 남기고 30초 뒤 다시 본다 |
| 둘 다 그 이상 | GTA 를 앞으로 가져오고(최소화면 복원) `AFKRefocusSettleMs`(800ms) 기다린 뒤, 위의 입력 조건을 다시 보고 누른다 |

- 0928 07:45 예약 작업이 띄운 크롬이 GTA 포커스를 가져간 뒤 입력이 끊겨 15분 만에(07:59) 방치 킥을 당한 뒤 넣은 동작이다. 전에는 다른 창이 앞이면 건너뛰기만 했다.
- 주입 입력까지 보는 까닭: 원격 데스크톱으로 쓰는 사람과 에이전트의 입력은 물리 입력에 안 잡힌다. 그때 GTA 를 가져오면 그 클릭은 사격으로, `T` 뒤 글자와 Enter 는 공개 채팅으로 게임에 들어간다. 대가로 에이전트나 예약 작업이 OS 입력으로 15분 넘게 쉬지 않고 다른 창을 조작하면 방치 킥을 못 막는다. 관리자 권한 창(작업 관리자 등)에서 치는 입력도 Main 의 훅은 못 보지만 전체 입력에는 잡혀 창을 뺏지 않는다.
- 키보드 훅은 60초마다 입력 없는 재설치로 유지하고, 실제 단축키 접수는 `gta-macro.log`의 `[hotkey]`로 확인한다. 상시 진단 키는 보내지 않는다. 예전 F24 점검 입력이 매 60초 전체 입력 유휴를 초기화해 AFK 전면화 기준에 도달하지 못하게 했기 때문이다. 사용자·원격 입력 보호 기준을 낮춰 우회하지 않는다.
- Main 을 켠 직후에는 훅이 물리 입력 시간을 0 부터 다시 센다. 훅을 깐 뒤 물리 입력을 한 번도 못 봤으면 전체 입력 시간으로 메우므로, 오래 비운 자리에서 다시 켜도 5분을 기다리지 않는다.
- 가져오기에 실패하거나 가져온 직후 포커스를 다시 잃으면 30초, 60초 뒤 다시 해 본다. 같은 앞 창과 유휴 구간에서 세 번 실패하면 추가 전면화를 멈추고 `refocus blocked` 로그와 경고를 남긴다. 사용자가 입력하거나 앞 창이 바뀌면 새 구간으로 판단한다. GTA가 다시 앞에 오면 AFK 입력을 재개한다. 기다리는 사이 사람이 돌아온 것은 실패로 세지 않는다.
- Windows 알림(`ShellExperienceHost.exe / New notification`)이 전면화를 막으면 `Move this notification to Notification Center`라는 UI Automation 버튼이 정확히 하나일 때만 한 번 눌러 알림 센터로 옮기고 복귀를 재시도한다. 승인·거절·알림 본문은 누르지 않는다. 창 신원과 마지막 입력 시점이 달라지거나 버튼이 모호하면 취소한다. 검사 프로세스는 최대 8초이며, 최근 입력과 다른 매크로 동작을 기다리는 동안에도 확인한다. 알림 처리 성공 뒤에도 GTA 포커스와 실제 AFK 입력 성공을 각각 확인해 로그에 남긴다.
- 앞 창에 직접 보내는 키는 앞 창이 입력 도구(`TextInputHost.exe`)거나 앞 창이 없을 때의 Alt 한 번뿐이다(0926 대응과 같은 조건, 로그에 `Alt 보조`). 다만 AHK 의 `WinActivate` 는 실패하면 스스로 Alt 를 두 번 누를 수 있다(AHK 소스 기준, 실측 안 함). 이런 Alt 는 전체 입력 시간에서 뺀다.
- 가져온 뒤에는 GTA 가 앞이므로 수익 자동화도 차례가 된 작업을 시작한다.
- `AFKRefocusIdleSec=0` 이면 가져오지 않고 전처럼 건너뛰기만 한다. `AFKUserIdleSec` 보다 작게 잡아도 `AFKUserIdleSec` 이 먼저 걸린다. 이 값은 Main 만 읽는다. `tools/earn-test/afk-guard.ahk` 는 `Config.ini` 를 안 읽고 자기 기준(아래)으로 가져오므로 0 으로 끌 수 없다.
- 로그 예: `refocus ok idle=312s 주입 포함 idle=312s 앞 창=chrome.exe / about:blank - Google Chrome`, `refocus 실패: 2초 안에 앞으로 오지 않음 idle=640s 앞 창=… (다음 시도 30초 뒤, 같은 까닭은 다시 적지 않음)`.
- 메뉴에서도 작은 마우스 왕복만 보내며, 사용자 조작이 시작되면 남은 움직임을 취소한다.
- 입력 없음 시간과 간격은 설정 창에서 바꾼다(5~600초, 30~600초). 전면화 기준 등 나머지 값은 `Config.ini`. 로그는 `%TEMP%\gta-afk.log`.

Vinewood 앱 열림 여부는 제목의 흰 글자와 같은 위치의 검정 배경을 함께 확인한다. 밝은 하늘을 앱으로 오인해 직원 파견이나 AFK 처리를 미루지 않도록 원본과 HDR 밝기 사본 모두 같은 배경 앵커를 사용한다. 제목 템플릿은 `tools/earn-test/build-afk-overlay-templates.ps1`로 실측 fixture에서 재생성하고, `test-afk-overlays.ps1`로 실제 제목과 밝은 빈 화면을 구분하는지 검사한다.

## 판매 차례 알림 (Num1)

디코 오버레이(DiscordChatHUD) 채팅 아래 판매 대기자 맨 위가 `Config.ini` 의 `SaleAlertName` 이 되면 삐 소리 세 번과 툴팁으로 한 번 알리고 스스로 꺼진다. 평소에는 꺼져 있고 Num1 로 켜고 끈다. 그 자리를 10초마다 한국어 OCR 로 읽는다.

## 상호작용 메뉴 매크로 (Num0 스낵)

M 을 열고 `Config.ini` 의 칸 수대로 Down·Enter 를 보낸다(스낵만 끝에 M 으로 다시 닫는다). 화면 확인이 없어 커서는 맨 위(Quick GPS) 기준이고, 게임이 마지막 커서 위치를 기억하므로 다른 항목에 두고 닫았으면 한 번 빗나간다. 칸 수 기본값은 공개 문서·매크로에서 가져온 것이라 안 맞으면 `[Settings]` 의 `Snack*` 을 고친다. 한 번에 하나만 돌고, 다른 것이 진행 중이면 툴팁만 뜬다.

내 부동산(아케이드 등) 안에서는 맨 위에 "… Management" 줄이 하나 더 붙는다. 설정 창의 "부동산 안/밖" 라디오(`MenuTopOffset`)를 맞춘다.

CEO·MC 는 평소 해제 상태로 둔다. 켜 두면 사업장이 습격 대상이 된다. 시험으로 등록했으면 그 자리에서 Retire·Disband.

## 이동·클릭 (F6 / F7 / F8)

F6 은 Shift+W, F8 은 W 를 누른 채 3초마다 LCtrl(벨럼 이륙 유지). 켜져 있는 동안 AFK 방지는 쉰다. 스크립트가 이동 키를 누른 채 끝나면 캐릭터가 계속 걸어가므로 종료·전체 멈춤·오류 때 매크로가 누른 키를 뗀다.

F7 자동 클릭은 커서가 게임 화면 안에 있을 때만 왼쪽 클릭을 반복한다(클릭마다 `ClickHoldTime` 50ms 누르고 `ClickInterval` 1ms 쉬므로 약 50ms 에 한 번). 문자·숫자·F키·Enter·방향키 같은 다른 키를 누르거나 커서가 게임 밖으로 나가면 멈춘다(0926: 커서가 설정 창 위에 남아 설정 창 버튼을 연타한 사고). 첫 클릭이 거절되거나 클릭 대기 중 End로 멈춰도 타이머를 다시 켜지 않는다. 설정 창 버튼으로 켜면 커서를 게임 가운데로 옮겨 준다.

## 인형 뽑기 (Num/ 한 판, Num* 반복)

아케이드 기계 앞 "Press E to play" 상태에서 누른다. E → W 5초 → D 5초 → Enter 순서이고 단계마다 왼쪽 위 안내 문구 이미지(`Images\Claw\`)를 확인한 뒤에야 다음 키를 보낸다. 안내가 안 보이면 아무 키도 안 보내고 멈춘다(캐릭터가 걸어가 버리는 사고 방지). 반복을 끄면 진행 중인 판은 다음 키 전에 멈추고, 중간에 멈춘 판은 다음 시작 때 먼저 내려서 정리한다. 이 복구 과정도 내리기 안내를 확인하지 못하거나 중단·포커스 이탈을 감지하면 Enter를 보내지 않는다. 해상도별 폴더(`Images\Claw\<가로>x<세로>\`)가 있어야 하고 2560x1600 만 루트에 있다. 이동 시간 값(`ClawForwardMs`, `ClawRightMs`)은 1920x1080, RT 켬, DLSS 품질/FG 2X, 120fps 에서 잰 것이다. 로그는 `%TEMP%\gta-claw.log`, 진단 상태는 `%TEMP%\claw-status.ini`.

## 수익 자동화 (F9 두 번)

저택 MCT를 거점으로 벙커 보급·DJ 교체·나이트클럽 창고 직원을 관리한다. GTA+의 Vinewood Club 앱으로 나이트클럽 금고를 회수하고 보석 집행 요원·스페셜 패키지 창고 직원을 파견한다. 현재 기본 설정은 `EarnMCTOnly=1`과 `EarnBunker`, `EarnDJ`, `EarnSafe`, `EarnWarehouse`, `EarnBailAgents`, `EarnCargoStaff`가 모두 1이다. Main 시작 시에는 MCT와 무관한 유휴 앱 작업만 자동으로 예약한다. 전체 수익 작업은 MCT 사업장 목록이나 확인 가능한 MCT 앞 대기 위치에서 F9를 두 번 눌러 시작하고, 다시 두 번 누르면 MCT 작업만 꺼지고 금고·앱 직원 파견은 계속 돈다. 진행 중인 MCT 묶음은 원래 순서대로 끝낸 뒤 꺼지며, 끌 때 따로 MCT 정리나 CEO 해제를 하지 않는다. 바뀌기 전에 한 번 더 두 번 누르면 끄기를 취소한다. 테러바이트 MCT(터치스크린 앞)도 지원한다. 테러바이트는 선 채 Space로 열고 닫으면 바로 접속 안내로 돌아오며 앉고 일어서는 단계가 없다. 저택 HDR의 `Press E to sit down.` 안내는 저장한 출력 변형별 텍스트·배경 템플릿을 모두 확인해 HDR 설정에 따른 렌더링 차이를 허용하되, 배경 검증은 유지한다. 템플릿이 놓치는 HDR 안내는 왼쪽 위에 OCR로 읽힌 `Press`와 `to sit down` 문구의 위치·높이가 맞는 경우에만 보완 판정한다. HDR의 MCT 대시보드 제목도 최대 55의 색상 차이를 허용하지만 같은 위치의 배경 템플릿을 함께 확인한다. 밝은 실내의 HDR 변형은 안내 상자 안의 글자 내부와 빈 배경 띠만 비교해 상자 밖 월드 픽셀을 인식에 쓰지 않는다. AFK 방지는 화면 판독과 별개로 작은 마우스 왕복을 사용한다. 지원 화면은 1920×1080 영어 UI이며 한글 UI는 지원하지 않는다. 적용 정책과 계산은 [수익 자동화 정책](docs/earner-policy.md), 실제 검증 범위는 [인계 기록](docs/earner-handoff.md)을 따른다.

의자형 MCT는 기존 E 착석·Enter 접속·우클릭 일어서기 경로를 유지한다. 테러바이트는 전용 접근 안내를 확인한 뒤 Space로 열고 Backspace로 닫는 별도 경로를 사용한다. 이미 열린 MCT에서 시작해도 닫힌 뒤 실제 안내로 종류를 구분하며 이전 방문의 종류를 재사용하지 않는다. 테러바이트에서는 CEO 해제 후 같은 자리의 전용 접근 안내를 다시 확인하고, 의자 탐색 회전이나 걷기를 보내지 않는다. 접근 안내를 확인하지 못하면 복구 대기로 남는다.

이번 테러바이트 장소 시험은 `tools/earn-test/earntest.ahk TerrorbytePlaceSmoke`로 전용 열기·닫기·제자리 안내 확인을 두 번 반복하는 범위다. CEO 등록·해제, 사업장 갱신·구매, 공통 종료는 호출하지 않는다. 기존 MCT 전체 자동화와 공통 CEO 문제의 재개를 뜻하지 않으며, 공통 CEO 해제까지의 정상 완료는 미검증이다. 해당 경로가 포함된 `TerrorbyteCycleSmoke`는 이번 완료 조건에서 제외한다.

스케줄러는 1초마다 때가 된 작업을 본다. 때가 된 작업이 여럿이면 예약 시각이 가장 오래된 작업을 먼저 고르고, 같은 시각이면 기존 목록 순서를 유지한다. 따라서 짧은 간격으로 다시 확인하는 벙커 작업의 예약이 이미 만료됐더라도 더 오래 기다린 금고 회수와 앱 직원 파견을 계속 밀어내지 않는다. 벙커·DJ·창고 직원은 MCT 작업이라 그 시점에 차례가 된 것들을 MCT를 한 번 열어 묶어 처리하고 한 번만 닫는다. 진행 중 새로 차례가 된 작업은 다음 회차다. MCT 화면이나 접속·앉기 안내가 없으면 입력 없이 최대 5초 기다리고 해당 MCT 작업을 3분 뒤 재시도한다. 위치를 찾기 위한 카메라 회전·시점 모드 전환·상호작용 메뉴 입력은 보내지 않는다. AFK MCT 정리도 확인된 MCT·사업장 화면 또는 확인창에서만 시작하며, DJ 이름 글자만으로 정리하지 않는다. 금고 회수와 앱 직원 파견은 그다음 Vinewood 앱에서 따로 한다. F9를 놓고 키보드·마우스 입력이 2초 동안 없으면 다음 확인에서 시작한다(보통 2~3초). 대기 중에는 오버레이에 입력 안정 또는 GTA 포커스 대기 이유를 표시한다. F9로 MCT 수익을 끄면 자동화는 멈추지 않고 진행 중 묶음이 끝난 경계에서 Vinewood 작업만 남긴다. End 전체 멈춤과 메모리 보호 종료는 안전 정리를 시작하지 않는 즉시 중단 경로다. CEO는 상호작용 메뉴를 먼저 열어 등록하지 않는다. MCT에서 사업장을 고를 때 뜨는 `Press L Ctrl to register as a CEO` 안내를 확인한 뒤 그 자리에서 등록하고, 묶음이 끝나 MCT를 닫은 뒤 한 번 해제한다. 이 안내는 커서를 사업장 버튼에서 치우면 사라지므로 안내를 읽는 동안에는 커서를 두고, 사업장에 들어간 뒤에 치운다. 다음 동작은 화면 템플릿과 영어 OCR로 확인하며, 판독 실패나 예상과 다른 확인창에서는 해당 동작을 중단하고 확인된 정리 경로로 복구한다. 실패·재시도·보류 이유는 `%TEMP%\gta-earn.log`에 남기며 복구 대기는 오버레이와 설정 창에도 표시한다. F9 운용에는 부동산 이동·세션 전환이 필요하지 않으며 현장 파견은 `EarnDispatch=0`이다.

벙커 기본값 `EarnBunkerIntervalSec=6720`은 보급 네 칸(80%) 소모를 선택하는 기존 설정이다. 기본 속도에서 112분에 해당하지만 생산 가속 여부나 경과 시간을 구매 허가로 쓰지 않는다. `1680`초의 1~5배 설정은 각각 실제 보급 20~100% 소모 경계를 선택한다. 구매 전 화면의 실제 보급량과 정확한 가격(칸 수 × $15,000)을 함께 확인한다. 생산 속도가 달라져도 다음 보급 관측은 현재 잔량에 따라 10초 또는 1분 뒤로 예약하고, 다음 20% 경계까지 실제 잔량 차이가 3% 이하이면 MCT에서 10초 간격으로 최대 4분 동안 재관측한다. MCT 종료·CEO 해제 중 그 예약이 이미 지났으면 정리 완료 뒤 최소 1분을 더 기다려 즉시 재진입하지 않는다. 구매·배송 확인 뒤에도 같은 규칙으로 새 잔량부터 확인하며, 관측 간격은 구매 주기가 아니다. 경계를 지나쳤으면 실제 다음 경계를 기다리고, 관측 기한을 넘긴 결과로 결제하지 않는다. 배송 중이면 추가 구매하지 않는다. 재고 만재는 판매 알림만 표시하고 보급 구매를 건너뛴다. 5분 뒤 재고를 다시 확인하며 다른 수익 작업은 계속한다. 중단은 사용자가 F9 또는 End로 결정한다.

MCT 등록·목록 갱신은 나이트클럽 Home을 열었다가 돌아오는 경로를 사용한다. 보급이 필요하지 않은 벙커는 갱신 목적으로 열지 않는다. MCT 보급 막대로 구매 후보가 된 경우에만 벙커에 들어가며, 내부 Supplies Level 막대가 MCT 관측보다 3%p 넘게 증가했으면 배송 도착 등 상태 변화로 보고 보급 메뉴·구매 입력 없이 MCT로 돌아온다. 내부 막대를 확인하지 못하면 구매를 진행하지 않는다. 내부 판독으로 결제 조건을 완화하지 않으며 기존 소모 경계와 확인창 가격 검사를 유지한다.

DJ 기본 목표는 95%다. 직원 업그레이드·일반 수입 배수에서 정상 주기는 100%와 95%의 $50,000 지급을 받은 뒤 90%에서 기존 DJ를 $10,000에 재고용하는 방식이다. 95%에서 100%를 만들기 위한 교체는 하지 않는다. 96분당 $100,000 수입에서 재고용 비용 $10,000을 뺀 $90,000이므로 매 지급마다 100%로 복구하는 것보다 순수입이 높다. 5분마다 Nightclub의 Home 화면을 새로 열어 인기도를 확인하고 95% 미만일 때만 Solomun/Tale Of Us를 재고용한다. 교체 뒤에는 Home → MCT → Home으로 한 번 재진입하고 최대 15초 동안 읽기만 반복해 증가를 확인한다. 갱신이 늦다는 이유로 재결제하지 않는다. DJ 지출 판단에는 이 Home 막대만 사용한다.

금고는 Vinewood 앱 사업장 목록의 모든 금고(나이트클럽·아케이드·에이전시·구조물 처리장·보석 사무소·의류 공장·세차장)를 한 줄씩 읽는다. 세차장은 한도 $100,000 안의 양수 잔액이면 관측 때마다 회수한다. 나머지 금고는 다음 입금(게임 하루 48분마다의 최대 입금)이 그 금고 한도를 넘길 금액이면 회수한다(예: 나이트클럽은 한도 $250,000·하루 $50,000 이라 $200,000 초과). 꽉 찰 때까지 기다리면 넘치는 입금이 버려진다. 행을 선택한 뒤 하단 `Claim $X from your <사업장> safe.` 문구의 금액을 읽고, 수거 직전에 같은 선택·금액을 다시 확인하고, 수거 후 `Your <사업장> safe is empty.`를 확인한다. 빈 금고의 회색 선택 행이 판독에서 빠지면 앱 제목과 정확한 사업장별 빈 금고 문구 하나로만 빈 금고를 확인한다. 수거 문구가 섞이거나 설명이 여러 개면 추측하지 않으며, 금액이 있는 금고의 선택 행 확인은 생략하지 않는다. 목록을 다 돈 뒤 앱·전화 닫힘을 확인한다. 다음 확인은 작업과 앱 닫기가 성공한 시각부터 `EarnSafeIntervalMin`(현재 설정 5분) 뒤로 정한다. 입금 횟수 예측이나 금고 알림으로 예약을 바꾸지 않는다. 한도·하루 입금 표는 `EarnVinewood.ahk`의 `EarnSafeLimits()`.

나이트클럽 창고 직원은 기본 10분마다 실제 재고·용량을 관측한다. 만재 품목이 3개 이상일 때만 `나이트클럽 창고 만재 N개: 판매 필요`로 알리되 자동화를 멈추거나 자동 판매하지 않는다. 0~2개에서는 나이트클럽 판매 알림을 띄우지 않고, 3개 미만으로 내려가면 나이트클럽 표시만 지운다. 벙커·각 스페셜 패키지 창고·격납고 알림은 별도로 보관해 함께 표시한다. 해당 사업장의 비만재 상태를 확인해야 지워지며, 다른 사업장 관측·판독 실패·조달 중 문구·F9 토글은 기존 경고를 지우지 않는다. 동일 대상의 같은 경고는 로그·툴팁을 반복하지 않는다. Main 재시작 뒤에는 새 관측으로 다시 표시한다. 직원 배치는 "3품목 만재 알림 후 15분 이내 전량 판매"의 창고 판매 순수익(토니 수수료 차감)을 대상으로, 부분재고와 판매 주기를 반영한 최대 21개 초기 조합의 표준 계획모형을 비교한다. 판매 0~15분과 생산속도 민감도를 반영한 보수 모형점수가 높으면 생산 중인 직원도 옮길 수 있다. 임의 중간 교대를 포함한 전역 최적이나 실제 수익 향상을 보장하지 않으며 가정과 계산은 [정책 문서](docs/earner-policy.md#나이트클럽-창고-직원)에 명시한다. 만재 직원부터 한 명씩 옮긴 뒤 전체 화면을 다시 읽는다. 이미 3품목 만재여도 빈 생산 자리 보충은 계속한다. 현재 화면 판독은 직원 5명을 모두 고용하고 각각 품목에 배정한 상태를 전제로 한다. 미배정 직원이나 담당 품목을 알 수 없는 직원이 있으면 자동 배정·고용을 시도하지 않고 중단한다. 품목을 누르면 뜨는 `Assign Technician` 확인창은 문구를 읽은 뒤 Confirm을 한 번 누른다. Vinewood 앱의 스페셜 패키지 창고·격납고 만재도 해당 대상의 구매·조달만 건너뛰며 다른 작업은 계속한다.

앱 직원 파견은 MCT 위치와 무관하다. 메뉴 없는 게임 HUD와 입력 유휴를 확인해 전화를 열며, MCT 진입·복귀 확인이나 CEO·MC 변경을 하지 않는다. 저택 MCT 앞에서는 확인된 `Press E to sit down.` 안내를 정상 기립 화면으로 인정하므로 직전 매크로 입력의 유휴 시간을 기다리지 않는다. 안내가 늦게 돌아오면 입력 없이 최대 3초 동안 다시 확인하며, 실제 키보드·마우스 입력과 열린 전화·메뉴는 계속 차단한다. 밝아진 체력 막대도 녹색의 가로 연속성으로 확인하되 전화·메뉴가 보이면 입력하지 않는다. 직원 확인과 앱 닫기가 성공한 시각부터 `EarnStaffIntervalMin`(현재 설정 5분) 뒤에 다시 확인한다. 직원 복귀 예정 시각이나 금고 입금 예측으로 확인 간격을 변경하지 않는다. 나이트클럽 창고 직원은 저장된 생산속도 추정으로 관측을 미루지 않고 설정된 간격을 유지한다. `Manage Staff Members`의 Bail Office에서는 준비된 Agent 1·2만 파견하고, Warehouse에서는 소유한 1~5개 창고를 순회한다. 스페셜 패키지는 선택 행의 이름·$7,500·준비 문구를 다시 확인한 뒤 창고당 한 번만 주문한다. 작업 중인 창고는 건너뛴다. 만재 창고나 격납고는 판매 알림만 남기고 그 대상에만 조달하지 않는다. 다음 창고와 다른 직원 파견은 계속하고, 수동 중단 여부는 사용자가 결정한다. 요청 후에는 최대 60초 동안 작업 중 문구를 기다린다. 5분 관측이나 평시 약 48분 복귀 시간이 무조건 재주문하는 주기는 아니다. 파견 도중 중단돼 결과를 확인하지 못해도 보류하지 않는다. 이미 보낸 요원·조달 중인 창고는 게임이 비활성으로 막아 다시 돈이 나가지 않으므로, 다음 차례에 화면을 다시 읽어 이어 간다. 이 기능은 Bail Office 금고 수거나 Hangar 파견을 포함하지 않는다.

2026-09-27에 기존 DJ 재고용과 배송 중 중복 결제 방지를 실측했다. 2026-10-03에는 벙커 재고 36%·보급 22%에서 구매를 건너뛰고 다음 경계를 예약한 뒤 CEO 해제까지 성공했다. DJ는 Home 91%에서 한 번 재고용한 직후 값이 그대로여서 시험이 중단됐지만, 추가 결제 없이 Home을 다시 열어 100%를 확인했다. 후속 DJ 작업은 Home 100%에서 무구매 후 CEO 해제까지, 나이트클럽 창고 작업은 이동 대상이 없어 배정을 유지한 뒤 CEO 해제까지 성공했다. 금고 작업도 Nightclub $150,000을 읽고 수거 없이 앱을 닫아 복귀했다.

10월 3일 09:50에는 빈 보급의 $75,000 구매와 배송 중 안내까지 확인했다. 구매 버튼·확인창의 글자 가장자리 차이로 판독이 실패하던 템플릿과, 창이 닫힌 뒤 배경이 밝아지기 전에 복귀를 시도하던 처리를 고쳤다. 후속 벙커 작업은 배송 중 안내를 읽어 중복 결제하지 않고 MCT 종료·CEO 해제까지 성공했다. MCT 접근 안내와 복귀 화면도 정해진 기한 안에서 나타나는 즉시 진행하며, 화면을 확인하지 못하면 추가 입력을 멈춘다.

앱 직원 모듈의 실제 전체 실행은 요원 1 파견, 작업 중인 요원 2 건너뛰기, 창고 4곳의 각 $7,500 조달과 작업 중 확인, 만재인 Foreclosed Garage 건너뛰기, 앱 종료와 MCT 앞 복귀까지 성공했다. 직원 모듈의 입력 없는 검사는 438건, 실제 저장 화면 8장의 OCR을 포함하면 462건을 통과했다. 남은 실전 검증은 실제 $250,000 앱 수거, 나이트클럽 직원 재배정과 장시간 연속 운용이다. 전체 검사는 `tools/ci/run-checks.ps1`의 `results.json`으로 확인한다. 기존 DJ·벙커 정책에는 실제 ChatGPT Pro 5/5 검토를 반영했으며 새 앱 직원 범위의 외부 검토는 브라우저 연결 실패로 미완료다. 코드 변경 자체가 Main 실행이나 F9 토글을 대신하지 않는다.

앱 첫 화면의 `Manage Staff Members`는 맨 위 기본 선택에서 `Up` 한 번으로 감아 이동한다. 현재 선택 줄 OCR이 빠져도 이 진입만은 `Up`을 기본 방향으로 사용하고, 이동 뒤 실제 선택 줄을 다시 확인한 다음 Enter를 보낸다. 직원 관리의 Hangar·Warehouse·Bail Office 목록이 확인되면 이동 방향은 실제 3개 행의 선택 막대 위치로 계산한다. 회색 행이 OCR에서 빠져도 목록을 2줄로 줄여 계산하지 않는다. 목표에 도착했는지는 실제로 읽힌 목표 이름과 선택 막대를 다시 확인한다. 목표 이름이 계속 읽히지 않으면 제한된 탐색 뒤 중단하고 Enter를 보내지 않는다.

별도 `EarnHangarStaff=1` 설정은 격납고 직원에게 $25,000 조달을 요청한다. 파견 뒤 회색 Hangar 이름이 판독에서 사라지면 앱 제목, Warehouse·Bail Office의 고정 위치, 격납고 행의 선택 막대와 전체 조달 중 문구를 함께 확인해 완료로 처리한다. 이 보완은 이미 작업 중인 직원의 확인에만 사용하며, 이름·가격을 못 읽은 상태에서는 결제하지 않는다.

모든 직원이 작업 중이면 회색 직원 관리 행의 이름이 사라져도 전체 작업 중 설명을 발견한 자리에서 탐색을 멈춘다. 다른 행으로 이동하거나 Enter를 보내지 않고 작업 중 상태를 재확인한 뒤 앱을 닫는다.

반복 예약과 오류 처리의 입력 없는 검사는 `powershell -NoProfile -ExecutionPolicy Bypass -File tools/earn-test/test-earner.ps1`로 실행한다. 실제 스케줄러 함수를 사용하지만 게임·창·키 입력은 대체하므로 장시간 게임 운용을 검증하는 시험은 아니다.

개별 작업 판독 실패·본문 예외는 `실패: 작업id`와 사유·연속 실패 횟수·다음 시도를 기록하고 다른 작업을 계속한다. 기본 1분 또는 작업이 지정한 재시도 간격을 쓰며, `EarnSoftFailMax`를 넘으면 간격을 늘려 최대 30분까지 기다린다. 실패한 작업은 MCT 미리 묶기에 들어가지 않아 재시도 대기를 지킨다. 앱·MCT 정리가 미확인이면 수익 스케줄러는 켜진 채 `복구 대기`로 남고, 30초부터 최대 5분 간격으로 기존 화면 확인을 거치는 정리만 다시 시도한다. 정리 완료 전에는 사업장 입력을 보내지 않으며, 복구 뒤 보류한 결과를 확정하고 나머지를 재개한다. GTA 종료·재시작, 입력 잠금 오류, 스케줄러 자체 예외는 기존 중단 정책을 따른다.

MCT 정리의 알려진 화면 대기는 판독 소요를 포함한 12초 기한으로 제한한다. 마지막 동기 이미지 검색 자체는 중간 취소할 수 없지만 기한을 넘긴 뒤 추가 판독이나 입력을 시작하지 않는다. MCT 제목과 착석 안내는 확인된 영역만 검색하며, 미확인 복구는 입력 점유를 풀고 다음 복구 시도까지 AFK 타이머가 다시 실행될 수 있게 한다. 화면을 두 번 못 읽었다는 이유로 복구를 해제하지 않는다. 알려진 화면이 없을 때도 메뉴 없는 HUD, 실제 보스 메뉴를 통한 해제, 메뉴 닫힘과 마지막 HUD 확인이 모두 있어야 복구 완료다.

DJ 확인창에 갇히면 마우스 AFK 신호만으로 방치 추방을 막지 못한다. AFK 정리는 두 DJ 재고용 확인창을 직접 인식해 Cancel로 닫고 기존 MCT 종료·보스 해제 경로를 따른다. 확인 템플릿은 DJ 이름, $10000, resident DJ 문구를 모두 유지하면서 Discord 채팅 오버레이에 가렸던 오른쪽 끝의 부가 문구는 제외한다. 이름이나 금액 자체가 가려지면 결제하지 않는다. 10월 12일 사고의 녹화 재생과 실제 실패 캡처를 대조해 확인한 차이다.

수익 자동화는 Windows HDR 설정을 바꾸지 않는다. 화면 판독은 HDR 켬·끔 어느 쪽에서도 동작하도록 HDR 변형 템플릿과 OCR 보완을 함께 쓴다. 10월 8일에 작업 구간만 HDR을 끄는 기능을 넣었다가, 작업마다 화면이 깜박여 거슬린다는 사용자 요청으로 10월 9일에 걷어냈다. 그 전 버전이 남긴 `%TEMP%\gta-earn-state.txt`의 `hdr_restore` 값은 더 읽지 않는다.

금고 수거·직원 파견·벙커 결제·DJ 재고용은 요청 전에 `%TEMP%\gta-earn-state.txt`에 `pending_safe`, `pending_staff`, `pending_bunker`, `pending_dj`를 저장하고 결과 확인 뒤 비운다. 저장을 확인하지 못하면 요청하지 않는다. 요청 결과가 미확인이거나 요청 후 사용자가 개입하면 해당 작업만 `보류`하고 나머지는 계속한다. Main 재시작이나 F9 재활성화도 이 기록을 지우지 않는다. 해당 거래의 게임 결과를 확인한 뒤 해당 `pending_작업id` 값을 비우고 F9를 다시 켜야 보류가 풀린다. 실패 기록은 성공 증거가 아니며 AFK 보호의 실제 입력·게임 idle 상태도 따로 확인한다.

현금 원장 저장에 실패하거나 거래 직후 pending 정리를 확인하지 못한 경우에도 `pending_작업id`를 유지해 해당 거래를 다시 요청하지 않는다. `%TEMP%\gta-earn.log`의 원장 오류와 실제 게임 내 결과를 대조한 뒤 해당 pending 키를 정리한다.

금고 수거는 Enter를 한 번만 보내고 요청 시점부터 화면 판독·대기를 포함해 최대 60초 동안 같은 사업장의 빈 금고 문구를 확인한다. 15초 뒤에도 결과가 미확인이면 추가 요청 없이 응답 대기를 연장한 로그를 남긴다. 일시적인 OCR 누락은 읽기만 재시도하며, 다른 사업장 선택·사용자 입력·포커스 이탈이나 기한 초과는 성공으로 처리하지 않는다. 끝내 확인되지 않은 거래는 기존 보류를 유지해 중복 수거를 막는다.

보석 집행 요원 파견 후 요원 행이나 앱 제목 OCR이 잠깐 빠지면 Enter를 다시 보내지 않고 최대 6회 읽기만 재시도한다. 선택된 회색 요원명이 HDR 화면에서 사라지고 일반 OCR 설명까지 잘리면 전체 앱 영역을 흰 글자 OCR로 다시 읽는다. 같은 제목·선택행과 작업 중 설명을 확인한 경우에만 파견 결과로 인정하며, 준비 상태로 추정하지 않는다. 실제 다른 요원 선택을 관측하면 즉시 해당 결과 확인을 중단한다. 전체 60초 기한과 사용자 입력·포커스 중단 조건을 유지한다. `tools/earn-test/test-earnstaff.ps1 -FixtureDirectory <경로>`는 `staff-frame-07.png` 준비 화면과 `staff-frame-14.png` 작업 중 화면이 있는 실측 폴더도 production OCR·선택행·상태 함수로 검사한다. `-BailBusyImage <PNG 경로>`는 회색 요원명이 빠진 실측 작업 중 화면의 일반·흰 글자 전체 영역 OCR과 다른 요원 선택 거부를 검사한다.

파견 완료 뒤 현재 요원 이름이 사라진 경우에는 같은 앱 제목·정확히 하나의 선택 슬롯·그 슬롯의 작업 중 설명을 다시 확인한다. 다른 요원으로 이동할 때는 목표 이름과 고정 행 위치도 확인해 두 행 사이의 방향키 한 번만 허용한다. 선택 막대나 작업 중 설명을 확인하지 못한 화면에서는 이동하지 않는다.

직원 관리의 Hangar·Warehouse·Bail Office 목록에서 선택된 회색 글자가 HDR로 사라지면, 정확한 앱 제목과 서로 다른 두 직원 이름의 고정 행 위치 및 유일 선택 막대를 확인한 뒤에만 세 슬롯 탐색을 허용한다. 목표 글자는 합성하지 않으며 Enter 직전 실제 목표 이름·선택을 다시 읽는다. 기본 직원 회귀는 실제 HDR 목록 캡처의 OCR과 선택 픽셀로 Bail Office에서 Warehouse까지 Up 한 번, Enter 없음도 검사한다.

이전 금고 방문·아케이드 복귀 경로의 실측과 실패 기록은 [9월 인계 기록](docs/earner-handoff.md)에 보존한다. 이 이동 경로는 현재 F9 금고 작업의 완료 조건에서 제외했다. 남아 있는 길찾기·블립 검사는 `tools/earn-test/test-earnnav.ps1`, `tools/earn-test/test-earnblip.ps1`이다.

시험은 `tools/earn-test/earntest.ahk`로 Main 없이 실행한다. 하네스 자체는 Main과 AFK를 켜지 않는다. 하네스는 8초 물리 입력 유휴를 최대 2분 기다리고, 시험 도중 사용자 입력·포커스 이탈·End가 감지되면 중단한다. 실행 제한은 25분이고 오류는 창 대신 로그와 표준 출력에 남긴다. `Status`·`Idle`·`PhoneStatus`는 전면화나 입력 없이 상태를 읽는다. `PhoneStatus`는 전화 테두리와 통화 종료 아이콘의 감지 결과를 구분한다. 시험 하네스의 세션 전환에는 추가 화면 검사(`SessionGuard.ahk`)가 적용되므로 필요한 메뉴 템플릿이 없으면 해당 키 전에 멈춘다.

MCT에서 일어선 뒤 게임 전화가 연결되면 통화 종료 아이콘을 확인하고 Backspace로 끊은 뒤 복귀한다. 10월 7일에는 Steam 녹화에서 맞던 아이콘이 실제 데스크톱에서는 허용 오차 40을 넘어 통화를 놓쳤다. 기존 아이콘은 허용 오차 60으로 보정하고, 실전 재검증에서 발견한 다른 크기의 아이콘은 `phone_call_end_live`를 기본 오차로 추가 확인한다. 실제 화면·녹화·전화 없는 화면을 비교하는 `test-phone-call-template.ps1`을 CI에 포함한다.

MCT에서 일어선 뒤 접근 안내를 다시 찾는 제자리 회전은 HDR 체력 막대를 판독 완료 후 250ms 간격으로 확인하고, 느린 메뉴 판독 뒤에는 이동 전 다시 갱신한다. 전화·앱·상호작용 메뉴·MCT 화면 검사는 회전 전과 판독 완료 후 3초 간격으로 수행한다. 접근 안내는 판독 완료 후 500ms 간격으로 확인하며, 안내와 메뉴 없는 HUD가 확인되면 남은 각도를 채우지 않고 바로 회전을 끝낸다. 매 이동 조각과 느린 판독 직후에 사용자 입력·포커스 이탈을 확인한다. 9초 제한에 닿으면 목표 도달을 마지막으로 확인한 뒤 추가 입력 없이 끝낸다. 일반 이동과 카메라 회전의 HUD 판정은 기존 조건을 유지한다.

작업 중 AFK 보호는 `tools/earn-test/afk-guard.ahk`를 별도로 실행한다. Main 없이 실제 사용자 입력 45초 유휴 뒤 약 120초마다 같은 2만큼의 마우스 왕복을 보낸다. 기존 포커스 복귀 조건과 공통 입력 잠금을 유지하며 Main·시험·GUI 실행기가 있는 동안 대기한다. F4로 켜고 끄며 상태는 `%TEMP%\gta-afk-guard-state.txt`, 입력 기록은 `%TEMP%\gta-afk.log`다.

```powershell
Start-Process -FilePath "$env:LOCALAPPDATA\Programs\AutoHotkey\v2\AutoHotkey64.exe" -ArgumentList '/ErrorStdOut tools\earn-test\afk-guard.ahk' -WindowStyle Hidden
```

AFK와 앱 진입은 같은 체력 막대 확인을 사용한다. 1920×1080 화면의 고정된 체력 줄에서 16개 표본 중 12개 이상의 녹색 우세를 확인하므로 HDR에서 밝아진 막대도 인식한다. 체력 막대는 전화·앱 안에도 보일 수 있어 기존 메뉴 제외 확인과 사용자 입력 유휴 확인을 함께 적용한다.

GUI 작업에서 확인한 구간을 직접 조작할 때는 `tools/earn-test/gui-input.ahk`와 `gui-input.ps1`을 쓴다. GTA가 이미 앞에 있어야 하며 Main·AFK를 켜거나 창을 전면화하지 않는다. 처음 시작할 때만 실제 사용자 입력 유휴 8초를 확보한다(최대 60초 대기). 이후 자기 입력 때문에 유휴 시간을 다시 기다리지 않는다. 실제 사용자 입력·GTA 포커스 이탈·End를 감지하면 보유 키를 놓고 종료하며, 전체 실행 제한은 25분이다. 다른 작업·매크로·Computer Use와의 조작권 직렬화는 계속 필요하다.

아래 PowerShell은 현재 디렉터리가 이 저장소 루트이고 AutoHotkey v2가 현재 사용자의 기본 위치에 설치됐다고 가정한다. 실행마다 새 빈 TEMP 디렉터리와 토큰을 만든다.

```powershell
$gtaRepo = (Get-Location).Path
$guiToken = [Guid]::NewGuid().ToString('N')
$guiSession = Join-Path $env:TEMP ('gta-gui-' + $guiToken)
New-Item -ItemType Directory -Path $guiSession | Out-Null
$guiAhk = Join-Path $env:LOCALAPPDATA 'Programs\AutoHotkey\v2\AutoHotkey64.exe'
$guiArgs = '/ErrorStdOut "' + (Join-Path $gtaRepo 'tools\earn-test\gui-input.ahk') + '" "' + $guiSession + '" "' + $guiToken + '"'
Start-Process -FilePath $guiAhk -ArgumentList $guiArgs -WindowStyle Hidden -PassThru
```

`Get-Content (Join-Path $guiSession 'state.txt')`의 상태가 `ready`인 것을 확인한 뒤 명령 하나를 보내고 `result-N.txt`를 확인한다. 입력을 묶는 범위와 화면 확인 시점은 스킬 정본 `~/dotfiles/codex/skills/gta-macro-ops/SKILL.md`의 메뉴·이동 규칙을 따른다. 확인한 시작 상태에서 고정된 탐색 구간을 한 호출로 보내고, 의미 있는 분기·실행 확정·구간 결과에서 캡처를 확인한다. 전송 성공은 화면 전환의 증거가 아니다. 아래 예시는 각각 별도로 실행하며 `hold`는 화면에서 확인한 장애물 없는 직선 구간에서 W/A/S/D 중 한 키를 최대 15,000ms 유지한다.

```powershell
& .\tools\earn-test\gui-input.ps1 -SessionDir $guiSession -Action tap -Key Backspace
```

```powershell
& .\tools\earn-test\gui-input.ps1 -SessionDir $guiSession -Action hold -Key W -HoldMs 6000
```

`navigate`는 `Up`·`Down`·`Left`·`Right`·`PgUp`·`PgDn` 1~20개를 한 번에 보낸다. `-InterKeyMs`는 150~500ms이며 기본값은 200ms다. Enter·Backspace 등 실행 확정·뒤로 키는 넣을 수 없다. 결과와 `navigate-N.log`에 완료 키 수와 `elapsed_ms`가 남는다.

프리모드에서 전화는 `tap -Key Up` 한 번으로 연다. Up을 빠르게 두 번 누르면 Snapmatic 카메라가 열리므로, 전화 열기 다음 탐색은 `Right` → `Up` 순서를 쓴다. 먼저 전화 홈의 `Job List`가 선택된 상태를 확인한다. 홈이 `Texts`에 열리면 해당 제목과 전화 프레임을 함께 확인한 뒤 `Down` 한 번으로 `Job List`에 이동하고 선택을 다시 검증한다. 그 다음 Contacts로 이동하고, 선택 결과를 확인한 뒤 별도 `tap -Key Enter`로 목록을 연다. 2026-09-27 수정 경로의 성공 실측은 이미 열린 Job List 홈에서 시작했으며, 프리모드부터 수정한 전체 경로는 아직 재검증하지 않았다.

```powershell
& .\tools\earn-test\gui-input.ps1 -SessionDir $guiSession -Action navigate -Keys @('Right','Up') -InterKeyMs 200
```

다음 연락처 구간은 Contacts 목록 최상단 `DE-SSANTA`가 선택된 화면에서 쓴다. 실행 뒤 `Franklin`이 선택된 화면이 종료 조건이다. 다른 이름이 선택돼 있으면 Enter를 이어 보내지 않고 현재 상태를 다시 확인한다.

```powershell
& .\tools\earn-test\gui-input.ps1 -SessionDir $guiSession -Action navigate -Keys @('Right','Right','Down') -InterKeyMs 200
```

Franklin 선택을 확인한 뒤 별도 `tap -Key Enter`로 전화를 건다. 연결 완료는 화면의 `Franklin CONNECTED`와 서비스 메뉴로 확인한다. 2026-09-27 실측에서 위 연락처 탐색 3키는 750ms였고, Enter·5초 대기·연결 화면 캡처는 별도로 5,843ms였다. 임무 요청의 접수·진행 여부는 그 다음 화면 증거로 판정한다([실측 기록](docs/earner-handoff.md)).

지도 확대·축소는 화면의 키 안내를 확인한 뒤 `-Action tap -Key PgUp` 또는 `PgDn`을 쓴다. `click`은 현재 캡처에서 읽은 물리 화면 좌표를 지정한다. GTA 클라이언트 영역 밖이면 거부하고, 영역 안에서는 커서 위치를 확인한 뒤 좌클릭을 100ms 누른다. 축소 캡처의 좌표를 그대로 넣지 않는다. DPI 처리를 포함한 실제 좌표 일치는 현장 화면으로 검증하며, 선택·실행 결과는 위 구간 기준에 맞춰 확인한다. 다음 좌표는 형식 예시다.

```powershell
& .\tools\earn-test\gui-input.ps1 -SessionDir $guiSession -Action click -X 960 -Y 540
```

범례 스크롤은 현재 커서가 범례 위에 있는 것을 확인한 뒤 `wheel`을 쓴다. 커서를 옮기지 않으며 매 틱마다 게임 포커스·사용자 입력·GTA 영역 안 커서 위치를 확인한다. `-Ticks`는 -5~5 중 0을 제외하며 양수는 위, 음수는 아래다. 탐색 구간 결과에서 캡처로 범례를 확인한다.

```powershell
& .\tools\earn-test\gui-input.ps1 -SessionDir $guiSession -Action wheel -Ticks -3
```

도구는 다음 행동을 자동으로 선택하거나 반복하지 않는다. 마지막 명령이 끝나면 `stop`으로 수신기를 종료한다. 진행 중인 이동의 즉시 중단은 End를 쓴다.

```powershell
& .\tools\earn-test\gui-input.ps1 -SessionDir $guiSession -Action stop
```

밝은 HDR의 MCT 벙커·나이트클럽 카드 제목은 기존 템플릿과 별도로 글자 내부만 비교하고, 같은 위치의 카드 배경도 확인한다. 글자 가장자리 때문에 전체 허용 오차를 늘리지 않는다.

## 전체 멈춤 (End) · 종료 (Pause 두 번)

End 는 도는 것을 전부 멈추고(카요 타이머 포함) 누른 키를 뗀다. AFK 방지만 남긴다. 게임 밖에서 End 가 안 잡히면 트레이 메뉴. Pause 는 전역 키라 노트북 Fn 오타로 꺼지지 않게 두 번 눌러야 한다.

F11 작텔은 작업 시작과 종료창의 마지막 대기까지 End와 게임 포커스를 확인한다. 종료창 대기 중 게임 포커스를 잃으면 해당 작텔은 중단하며, 게임으로 돌아와도 자동으로 이어서 No를 누르지 않는다.

## 매크로가 지키는 것

- Esc 를 게임에 보내지 않는다. Rockstar 런처·스팀 Big Picture 가 앞이면 종료 확인으로 받는다. 뒤로 가기·No 는 Backspace.
- 게임 종료·세션 나가기·스토리 모드 확인창에 매크로가 보내는 키는 둘뿐이다. F5 는 문구가 "quit this session" 으로 확인될 때만 Enter(OK), F11 은 게임 종료 확인창에 60초 뒤 Backspace(No). 그 밖에는 아무 키도 보내지 않는다. "quit this Job?"(작업 로비 나가기)은 매크로가 다루지 않고 직접 Backspace → Yes 로 나온다.
- 키를 보내기 전마다 GTA 가 앞인지 본다. 진행 중인 시퀀스(메뉴 매크로·세션 이동·작텔·인형 뽑기)는 포커스가 빠지면 그 자리에서 멈춘다. 수익 자동화 타이머는 다른 창을 전면화하지 않는다. Main의 AFK 방지는 물리 입력과 주입 입력이 둘 다 `AFKRefocusIdleSec`(기본 300초) 넘게 없을 때만 전면화한다. 별도 작업 AFK 실행기는 위에 설명한 유휴 조건(45초)에서 전면화한다. 설정 창의 명시적 실행 버튼은 GTA를 앞으로 가져온다.
- 초대 전용 세션·수익 자동화·작텔 알림은 메뉴에 들어간 직후 첫 키가 씹히는 일이 잦아 누른 횟수가 아니라 화면으로 판정한다. 상호작용 메뉴 매크로와 F11 의 Space → Enter 는 화면을 보지 않고 정해진 횟수·간격으로만 보낸다.
- CapsLock 이 켜져 있으면 AHK 가 키 앞뒤로 CapsLock 을 눌러 특수 능력이 발동하므로 `SetStoreCapsLockMode false`(0926 원인 확정).
- 오류 대화상자는 띄우지 않는다(포커스를 빼앗아 AFK 방지까지 막는다). `%TEMP%\gta-macro.log` 의 `[error]` 줄과 툴팁으로 알린다. 예외는 시작 때 `Config.ini` 가 없을 때의 알림창 하나다.

## 설정 (Config.ini)

`[Features]` 로 기능을 켜고 끈다(0 이면 키가 등록되지 않고 설정 창 버튼도 비활성). `[Hotkeys]` 는 키, `[Settings]` 는 시간·칸 수. 설정 창에서 바꾼 값(`MenuTopOffset`, AFK 두 값, `OverlayEnabled`)은 재시작 없이 반영된다. 나머지는 손으로 고친 뒤 설정 창 "다시 불러오기". 이것은 스크립트를 다시 시작하는 것이라 돌던 기능은 멈추고 AFK 방지·오버레이는 시작 설정대로 다시 켜진다.

- BOM 없는 UTF-8, CRLF. BOM 이 있으면 첫 섹션을 못 읽는다(발견하면 매크로가 떼고 다시 저장).
- 값 줄 끝에 `;` 주석을 붙이면 주석까지 값으로 읽힌다. 주석은 줄을 따로 쓴다. 숫자가 아닌 값은 기본값으로 대체하고 `[config]` 로그를 남긴다.

꺼 둔 기능: `Teleport=0`(CEO/MC 재등록 텔레포트. 휴대폰 경로가 Quick Join → Random 으로 바뀌어 이름대로 동작하지 않고, 해체 뒤 눈 감고 누르는 키가 작업 로비에서 나간다), `CasinoFingerprint=0`.

## 로그

메모리 보호는 1분마다 시스템 커밋과 GTA 개인 커밋을 읽는다. 기존처럼 정수로 반올림한 시스템 커밋이 `MemWarnPct`(기본 80%) 이상이면 한 번 경고한다. 경계에서 79↔80%를 오가도 반복하지 않으며, 경고선보다 5%p 낮은 값(기본 75%) 이하로 회복한 뒤에만 새 경고를 허용한다. 이 동안에도 `MemClosePct`(기본 92%) 이상으로 악화되면 위험 알림을 별도로 한 번 남긴다. `%TEMP%\gta-mem-state.txt`에 마지막 관측과 경고 단계를 저장해 Main 재시작에도 같은 경고를 반복하지 않는다. GTA PID와 OS 생성 시각이 모두 같고, 세 메모리 임계값이 같으며, 마지막 관측이 15분 이내인 경우에만 복원한다. GTA 종료·새 실행, 정책 변경, 오래되거나 손상된 파일은 새 경고부터 시작한다. 저장 실패는 진단 로그에 남기고 다음 관측에서 재시도하며, 원시 단계 변화와 10분 측정 기록은 계속 남긴다. 이것은 경고 이력 보존이며 RAM 사용량 감소나 메모리 누수 해결이 아니다. 위험 상승과 보호 종료는 저장 이력과 별도로 현재 측정에서 판단한다.

보호 종료는 알림 억제와 별개다. 시스템 커밋이 `MemClosePct` 이상이고 GTA 개인 커밋도 `MemCloseMinGB`(기본 25GB) 이상이면 즉시 수익 자동화를 끄고 GTA를 닫는 기존 조건을 유지한다. `MemClosePct=0`은 보호 종료와 상향 알림을 끄고, `MemWarnPct=0`은 경고 알림만 끈다. 경고는 시스템 전체 메모리 압박을 뜻하며 GTA 누수의 증거는 아니다. 원시 단계 변경과 10분 측정 기록은 중복 알림 억제 중에도 계속 저장한다.

10분 측정 기록 줄 끝에는 맥락이 붙는다. 직전 기록 대비 GTA 커밋 증가 속도(`증가 NMB/분`), 수익 자동화 상태(`수익 켜짐(작업명)`·`수익 꺼짐`), 그리고 `%TEMP%\gta-mem-note.txt` 첫 줄(`메모 ...`, 60자까지)이다. 1016 실측에서 GTA 커밋은 캐릭터가 밖에 있을 때만 분당 110~160MB 늘고 테러바이트·사업장 실내에서는 멈췄다. 세션 종류(초대 전용·공개)처럼 매크로가 알 수 없는 조건은 메모 파일에 적어 두면 기록마다 함께 남아 나중에 구간별로 비교할 수 있다. 파일이 없거나 4KB 를 넘으면 메모는 생략한다.

프레임 급락 감시는 `tools\frame-watch\install.ps1`로 설치한다. 기존 FPS 기록에 전면 상태와 GPU 메모리를 붙이고 급락 전후 자료를 보존한다. [감지 기준과 기록 확인](tools/frame-watch/README.md)을 따른다.

FPS 공급기는 PresentMon v1 출력 형식을 명시하고 하나의 ETW 세션을 유지한다. `%LOCALAPPDATA%\gta-perf\frames\YYYYMMDD\`에 수신 시각 `CapturedAt`을 붙인 원본 CSV를 10분 단위로 보존하며, 유효 FPS 계산에서 제외한 NA 프레임도 남긴다. 원본은 약 1초마다 디스크로 내보내고 자동 삭제하지 않는다. 강제 종료 직전의 버퍼나 저장 장치 장애까지 무손실을 보장하지는 않는다. 디스크 여유 공간과 자료 보존 기간은 운영자가 관리한다.

같은 폴더의 `status.json`은 마지막 요약 저장 시각·성공 여부, 원본 경로·행 수, 마지막 출력·유효 프레임 시각과 오류를 표시한다. `etw_status`에는 이벤트·버퍼 손실과 PresentMon 버퍼 상태도 남는다. 이 상태 출력은 프레임 원본이나 무출력 감지 시각에 섞지 않는다. 빈 FPS나 센서·저장 오류는 `health.jsonl`, PresentMon stderr와 헤더·원본 저장 실패는 `frames\errors.log`에 남는다. 헤더가 맞지 않거나 수집기가 종료되면 최대 분당 한 번 재시작한다. 게임이 전면인데 프레임 stdout이 60초 이상 멈춘 경우에도 재시작하며, 백그라운드의 무출력은 상태만 기록한다. 센서 조회 실패가 정상 FPS 행의 저장을 막지 않는다. 날짜별 요약은 행 시각과 같은 날짜 파일에 기록한다. 입력 없는 회귀검사는 `tools\tests\frame-feed.tests.ps1`이다.

| 파일 | 내용 |
|---|---|
| `%TEMP%\gta-macro.log` | 공통. `[jobwarp]` `[botwarp]` `[session]` `[menu]` `[hotkey]` `[config]` `[stop]` `[panel]` `[screen]` `[error]` |
| `%TEMP%\gta-afk.log` | AFK 방지 |
| `%TEMP%\gta-claw.log` | 인형 뽑기 |
| `%TEMP%\gta-earn.log` | 수익 자동화 |
| `%TEMP%\gta-earn-ledger.tsv` | 확인된 자동화 수입·지출. 부호 있는 금액, 거래, 출처, 근거를 기록 |
| `%TEMP%\gta-mem.log` | 시스템·GTA 커밋, 원시 단계, 최고 알림 단계(`alert`) |

MCT 벙커 막대 판독은 `[bunker-bar] kind=green/blue`에 실제 표본 좌표·RGB·개별 판정과 비율을 기록한다. 파랑 보급은 B가 R과 G보다 각각 30 넘게, 초록 재고는 G가 R과 B보다 각각 30 넘게 높은 표본만 센다. 밝은 빈 막대가 재고 99%로 집계된 실제 표본은 제외하지만, 혼합된 경계 픽셀은 빠질 수 있어 한 표본당 약 0.77%p의 판독 해상도와 함께 판단한다. 이 진단은 기존 판독 표본만 기록하고 추가 화면 읽기를 하지 않는다.

로그는 잘리지 않고 계속 쌓인다. 설정 창의 최근 로그에는 앞의 둘만 보인다.

원장은 금고 수거, 벙커 보급, DJ 재고용, 특수 화물과 격납고 조달처럼 자동화가 거래 금액과 완료 상태를 함께 확인한 변화만 기록한다. 거래 뒤 `gta-earn.log`에 최근 60분의 확인 수입·지출·순현금흐름을 남긴다. 창고 판매는 사용자가 직접 진행하며 자동화가 판매 완료 금액을 관측하지 않으므로 이 합계와 원장에 포함하지 않는다. 따라서 이 값은 자동화가 확인한 현금흐름이지 전체 게임 순수익이나 현재 계좌 잔액은 아니다.

원장 사본의 출처별·시간대별 합계는 [오프라인 현금흐름 보고서](tools/earn-ledger-report/README.md)로 확인한다. Python CLI에 입력 경로와 표시 시간대를 지정하면 HTML·JSON·CSV를 생성한다. 잘못된 행과 동일 행 후보, 기록 공백의 한계를 함께 표시하며 게임이나 원장을 변경하지 않는다.

MCT 진입·정리 실패(`멈춤: MCT…`)는 그 순간의 GTA 클라이언트를 `%TEMP%\claude\gta-earn-fail-<시각>-<사유>.png`로 절반 축소해 남긴다. 포커스를 바꾸지 않고 찍으며 3초 안의 중복은 한 장만, 오래된 것부터 지워 30장만 둔다. 로그의 사유와 이 캡처를 짝지어 화면이 왜 안 잡혔는지 본다.

F9 진단은 `gta-macro.log`의 `[hotkey] Earner` 기록으로 등록, 키 접수, 두 번째 누름 대기, 확인 시간 초과, 실행 시작·반환·예외를 순서대로 확인한다. 각 기록에는 Main PID와 전경 프로세스가 포함된다. GTA 밖의 F9도 원래 키 동작을 통과시키며 무시 사유를 기록한다. 첫 누름 후 시간이 지나면 확인 대기를 만료시키고 기록한다. 실제 켜짐·꺼짐과 작업 결과는 `gta-earn.log`에서 이어 확인한다. 로그 저장 실패는 기존 키 동작을 막지 않는다.

## 따로 실행하는 스크립트

`Main.ahk` 에 포함되지 않는다. 키가 겹치니 매크로와 같이 켜지 않는다.

- `bunker.ahk`: F9 토글(전역 키). 커서를 좌표로 옮기고 Enter 를 보내는 것과 시간만으로 벙커 보급을 27분 25초마다 산다. 화면 확인 없음, `Config.ini` 안 읽음. F12 종료.
- `KeyHoldTest.ahk`: F10. M 다음 바로 Enter 를 보내 메뉴가 열리는지 보는 시험. `Config.ini` 를 읽는다(`KeyHoldTime`·`MenuControlDelay`). F12 종료.
- `LCtrlSpammer.ahk`: F10 토글. 100ms 마다 LCtrl. `Config.ini` 안 읽음. F12 종료.
- `tools\gta-perf-watch.ps1`: 작업 스케줄러가 10분마다 돌리는 성능 감시. 게임에 입력은 안 보내고, 게임이 꺼져 있을 때 `settings.xml` 의 그래픽 단계를 바꾼다. 기록은 `%USERPROFILE%\gta-perf\`.
- `tools\kick-watch\kick-watch.pyw`: 작업 스케줄러 "GTA Kick Watch" 가 5분마다 pythonw 로 띄우는 킥 원인 기록기(이미 돌고 있으면 바로 끝난다). 게임과 매크로에 입력을 보내지 않고 `Main.ahk` 와 키가 겹치지 않는다. 기록은 `%USERPROFILE%\gta-kick\`: `fg.log`(전경 창 변화), `events.log`(세션 변경과 AFK 로그), `shots\`(세션 변경 2·15·45초 뒤 전체 화면), `observations.jsonl`(5초마다 전경·커서·OS 입력 시각), `afk-shots\`(AFK 입력 로그 전후와 세션 변경 직전 GTA 영역). [기록의 의미와 원인 분리 시험](tools/kick-watch/README.md)을 따른다. 입력 실행 로그는 게임의 방치 시간 초기화 성공을 뜻하지 않는다.

별도로 쓰는 외부 도구는 로컬 `third_party/` 에만 두고 저장소에서는 추적하지 않는다(1010 저장소 정리, 매크로가 쓰지 않음).

- `third_party/Lester-Ver2.0/`: 자체 Python 앱. 그 디렉터리의 README 에 따라 의존성을 설치하고 `python main.py`로 실행한다.
- `third_party/CodeSwine GTA5O - Private Public Lobby V1.0.1/`: `CodeSwine-Private_Public_Lobby.exe`와 인접한 DLL·설정.

실측 캡처·영상(`docs/evidence/`)도 로컬에만 둔다. 근거 화면은 PR 본문에 첨부하고, 시험이 쓰는 화면만 `tools/earn-test/*-fixtures/` 에 넣는다.

MCT 복귀 회전 종료 시 `[mct-turn]`은 실제 마우스 입력 조각 수와 누적 단위, 전체 경과 시간, 목표·체력·메뉴 판독 횟수와 시간을 기록한다. `read_ms`는 기존 제한 계산에 더한 판독 시간이며 마지막 목표 확인은 `terminal_ms`로 따로 기록한다. `budget_kind=total-cap`은 전체 90초 상한, `nonread`는 판독 시간을 제외한 9초 예산이다. 입력 단위는 게임 화면의 실제 회전 각도나 이동 거리를 증명하지 않는다.

MCT 착석 배경의 `screen-probe`는 `original_xy`와 `gain_xy`에 각각 성공한 검색 좌표를 보존한다. 원본이 원점 외 위치를 찾고 최종 판정도 실패한 경우에만 30초 간격으로 같은 Main에서 240×24 후속 표본을 읽는다. `origin_probe=followup`의 `sample_delta_ms`는 원본 검색 종료부터 캡처 시작까지 시간이며, `mask`, `exceeded`, `max_rgb`, `max_diff`, `worst_xy`는 투명색을 제외한 마스크 통계다. 이 표본은 검색 당시의 동일 프레임을 보장하지 않으며 판정이나 허용치를 변경하지 않는다.

원점 후속 표본은 이미 읽은 메모리 그대로 `%TEMP%\gta-mct-origin-followup.bmp`에 최신 한 개만 저장한다. 로그의 `bmp` 경로와 시각을 함께 확인해야 하며, 후속 진단이 파일을 덮어쓰기 전에 회귀 자료로 복사한다. 저장 오류는 통계와 기존 화면 판정을 변경하지 않는다.


### 직접 누른 이동 키 보호

매크로 대기 중 사용자가 W를 누르면 중단·정리 과정에서 W 해제 신호를 보내지 않는다. 자동 걷기·달리기와 인형 조작에도 같은 보호를 적용한다. 키 전송은 누른 Shift를 임시 해제하지 않으며, 달리기 매크로는 왼쪽 Shift만 관리해 오른쪽 Shift와 혼동하지 않는다. W 또는 어느 쪽 Shift든 눌린 동안에는 정기 키보드 훅 재설치를 미룬다. 이 보호는 매크로의 입력 처리 범위이며 게임이나 장치에서 발생하는 모든 끊김을 해결했다는 뜻은 아니다.

### DJ 실패 영상 보존

DJ 결과 확인 실패의 전후 영상·로그를 보존하려면 [DJ 증거 기록기](tools/dj-evidence/README.md)를 설치한다. 기존 Steam 녹화에서 실패 전 2분과 뒤 35초의 완성된 영상 조각을 별도 보관한다. 매크로 입력이나 보류 상태는 바꾸지 않으며, 기록기 재시작 뒤에도 수집을 이어간다. Steam 녹화 중단이나 디스크 부족은 별도로 확인해야 한다.

### Main 시작 후 유휴 앱 자동 실행

Main을 켜면 GTA가 실행되고 물리 입력이 설정된 유휴 시간을 넘긴 뒤 금고 수거와 앱 직원 파견을 예약한다. 다른 매크로나 카요 타이머가 실행 중이면 기다리며, 앱 실행 중 다른 매크로가 시작되거나 사용자 입력·포커스 이탈이 발생하면 중단한다. AFK 방지 자체는 대기 이유가 아니다. 금고와 직원의 기존 활성화 설정과 첫 대기를 따르며, 이후에는 성공 완료부터 설정된 간격을 기다린다. 실패 재시도 간격과 거래 보류 상태는 유지한다.

유휴 앱 모드는 MCT를 찾거나 들어가거나 의자로 복귀하지 않으며 보스 상태도 변경하지 않는다. F9 두 번으로 기존 전체 수익 모드를 켠다. 다시 F9 두 번으로 끄면 진행 중 MCT 정리가 확인된 뒤 유휴 앱 모드로 돌아간다. 앱 작업 중 전체 모드를 요청하면 그 작업과 복구가 끝난 뒤 전환한다. 전환 시 다음 예약과 거래 보류를 보존한다.

End 전체 멈춤은 유휴 앱 예약과 시작 대기까지 끈다. 종료 정리 실패, 게임 종료·재시작, 치명 오류 뒤에도 자동 재시작하지 않는다. End 뒤 F9는 전체 수익을 시작하며, 유휴 앱만 다시 시작하려면 Main을 재시작한다. 복구 대기 중 전체 수익을 끄면 복구 미확인 사유를 표시하고 자동 재개하지 않는다. 오버레이와 설정 창은 유휴 앱 모드를 구분해서 표시한다.
